# TAE 2026 — спецификация синтетического эксперимента

## 1. Задача

Синтетический эксперимент проверяет не качество LightGBM и не воспроизводит CDC Natality. Его цель — изолировать ошибку протокола оценки:

> если доступные для скоринга группы имеют разный размер, одинаковая доля отбора внутри каждой группы меняет одновременно и состав доступной группы, и абсолютное число отобранных людей.

Основная величина:

**искажение = эффект при отборе одинаковой доли каждой группы − эффект при одинаковом абсолютном числе отборов.**

В точной декомпозиции это искажение равно компоненте дополнительной ёмкости отбора.

---

## 2. Единица симуляции

Один повтор содержит:

- 100 000 искусственных наблюдений в оценочной популяции;
- независимую калибровочную популяцию из 50 000 наблюдений для общего порога;
- один общий набор скрытых рисков, исходов и случайных чисел для сравниваемых условий внутри повтора.

Всего по умолчанию 100 повторов.

Базовый seed: `2028`.

---

## 3. Скрытый риск и исход

Для каждого наблюдения:

`Z ~ Normal(0, 1)`.

`Z` — скрытая склонность к неблагоприятному исходу.

Исход:

`Y ~ Bernoulli(sigmoid(alpha + beta * Z))`.

В конфиге:

- целевая распространённость события: 10%;
- `beta = 1.0`;
- `alpha` не задаётся вручную: скрипт решает его численно так, чтобы ожидаемая распространённость была 10%.

Это один абстрактный бинарный исход; отдельные синтетические аналоги preterm/NICU/LBW не нужны, потому что эксперимент проверяет метод оценки.

---

## 4. Оценка риска модели

Скор модели:

`R = Z + sigma * epsilon`, где `epsilon ~ Normal(0,1)`.

Меняем `sigma`:

| Уровень | sigma | Ожидаемая корреляция R с Z |
|---|---:|---:|
| good | 0.50 | ~0.894 |
| medium | 1.00 | ~0.707 |
| weak | 2.00 | ~0.447 |

Никакая ML-модель здесь не обучается. Это намеренно: качество ранжирования регулируется одной прозрачной величиной и не смешивается с обучением или гиперпараметрами.

---

## 5. Доступность для скоринга

Для каждого наблюдения генерируется индикатор доступности:

`A ~ Bernoulli(sigmoid(gamma0 + gamma1 * Z))`.

`gamma0` автоматически решается отдельно для каждого условия, чтобы ожидаемая доля доступных была равна заданной.

Доли доступных:

- 50%;
- 70%;
- 90%.

Связь доступности со скрытым риском:

| Сценарий | gamma1 | Смысл |
|---|---:|---|
| `higher_risk_less_available` | -1.0 | более рискованные наблюдения реже доступны |
| `risk_independent` | 0.0 | доступность не связана с риском |
| `higher_risk_more_available` | +1.0 | более рискованные наблюдения чаще доступны |

Связь задаётся со скрытым риском, а не напрямую с уже реализованным исходом. Это сохраняет временную логику: доступность не зависит от будущего события напрямую, но через общий риск возникает связь доступности с исходом.

---

## 6. Два набора кандидатов

В каждом условии есть:

- `available_subset` — только наблюдения с `A=1`;
- `all_population` — вся оценочная популяция.

Обе группы используют **один и тот же вектор оценок риска** в данном повторе и уровне качества модели.

---

## 7. Ресурс отбора

Проверяются три номинальные доли:

- 5%;
- 10%;
- 20%.

Для top-q бюджет определяется как `round(q * N)`.

Минимальная ожидаемая доступность равна 50%, а максимальный общий бюджет — 20% всей популяции. Поэтому общий абсолютный бюджет по дизайну существенно меньше размера доступной группы.

---

## 8. Три протокола оценки

### Протокол A — одинаковая доля каждой группы

`B_available = round(q * N_available)`

`B_all = round(q * N_all)`

Абсолютное число отобранных различается.

### Протокол B — одинаковое абсолютное число отборов

Для обеих групп:

`B = round(q * N_all)`.

Это основной протокол для выделения эффекта расширения набора кандидатов при фиксированном ресурсе.

### Протокол C — один общий порог

В независимой калибровочной популяции находится порог оценки риска, соответствующий верхним q%. Затем один и тот же порог применяется к `available_subset` и `all_population`.

Число реально отобранных может различаться.

---

## 9. Метрики

Для каждого протокола и сценария сохраняются:

- `eligible_n`;
- `selected_n`;
- `true_positive_n`;
- `precision`;
- `recall_among_eligible`;
- `population_event_capture`;
- `event_availability_ceiling`.

Основная метрика:

`population_event_capture = TP / число всех событий в полной оценочной популяции`.

Знаменатель не меняется между сценариями.

---

## 10. Точная декомпозиция

Обозначим `C(S,B)` — population event capture для набора кандидатов `S` и абсолютного бюджета `B`.

Для доступной и полной популяций:

`B_available = round(q * N_available)`

`B_all = round(q * N_all)`.

Наивная разница:

`C(S_all, B_all) - C(S_available, B_available)`.

Компонента доступности:

`C(S_all, B_all) - C(S_available, B_all)`.

Компонента дополнительного ресурса:

`C(S_available, B_all) - C(S_available, B_available)`.

Проверяем тождество:

`наивная разница = доступность + дополнительный ресурс`.

На уровне TP тождество должно выполняться абсолютно точно. На уровне долей допускается только машинная погрешность `<= 1e-12`.

Основное синтетическое «искажение»:

`distortion = naive_top_fraction_effect - fixed_budget_availability_effect`.

По конструкции оно равно компоненте дополнительного ресурса.

---

## 11. Сетка эксперимента

Без учёта повторов:

- 3 доли доступности;
- 3 типа связи доступности с риском;
- 3 уровня качества оценки;
- 3 уровня ресурса.

Итого `3 × 3 × 3 × 3 = 81` условий.

При 100 повторах: 8 100 комбинаций условие-повтор до разворачивания по трём протоколам и двум сценариям.

---

## 12. Выходные файлы

Скрипт создаёт:

- `synthetic_protocol_results.csv` — все протоколы и сценарии на уровне повтора;
- `synthetic_protocol_comparisons.csv` — разницы `all_population - available_subset`;
- `synthetic_decomposition.csv` — точная декомпозиция на уровне повтора;
- `synthetic_condition_replicates.csv` — реализованная доступность и event ceiling;
- `synthetic_comparison_summary.csv` — агрегированные сравнения протоколов;
- `synthetic_decomposition_summary.csv` — агрегированная декомпозиция;
- `synthetic_summary.md` — автоматически собранная краткая сводка;
- `synthetic_experiment.locked.yaml` — копия использованного конфига;
- `synthetic_manifest.json` — параметры, версии, хэши и результаты invariant checks.

---

## 13. Проверки корректности

Скрипт аварийно завершает работу, если нарушено хотя бы одно из условий:

1. в протоколе A `selected_n != round(q * eligible_n)`;
2. в протоколе B абсолютный `selected_n` различается между двумя сценариями;
3. в протоколе C порог различается между сценариями;
4. меняется полный знаменатель событий;
5. полный бюджет превышает число доступных наблюдений;
6. TP-декомпозиция имеет ненулевую ошибку;
7. ошибка декомпозиции population capture превышает `1e-12`;
8. `distortion` не равен компоненте дополнительного ресурса.

---

## 14. Запуск

Из корня репозитория:

```bash
python scripts/experiments/run_tae_synthetic.py \
  --config configs/canonical/synthetic_experiment.yaml
```

Ожидаемый каталог результатов:

```text
results/tae_2026_synthetic/
```

Перед научной интерпретацией полного запуска рекомендуется сначала выполнить `tests/test_tae_synthetic.py`.
